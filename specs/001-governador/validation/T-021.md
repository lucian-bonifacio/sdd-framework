### Avaliação nativa por prefixo
Casos CodexPolicyTests usam subprocess com tokens:

codex execpolicy check --rules <checkout>/src/sdd_framework/assets/integrations/codex/sdd-git.rules -- <tokens do comando>

Isso interpreta as regras e retorna JSON; não executa o Git representado. A
carga também valida match/not_match embutidos na regra. Observado:

| Tokens/cenário | Resultado |
|---|---|
| git status --short; git diff --check; git log -5 --oneline; git show HEAD; git rev-parse HEAD (avaliações separadas) | matchedRules vazio e nenhuma decision do SDD; não é allow de elevação, e as permissões normais da sessão continuam valendo. |
| commit, push --force, pull, merge, rebase, reset --hard, restore, clean -fd, branch -D | decision prompt. |
| add, switch -c, checkout --, fetch, stash pop, config | decision prompt; operações ainda não liberadas não receberam allow. |
| git -C outro push; git -c alias.publicar=push publicar; git --git-dir outro/.git push | decision prompt para as formas separadas avaliadas. |
| Regra pessoal allow para git + política SDD para push | prompt prevalece. |
| Regra pessoal forbidden para git push + política SDD | forbidden prevalece. |
| --git-dir=outro/.git, alias particular e bash -lc contendo encadeamento | Sem allow da política SDD; não são apresentados como bloqueados universalmente pelos prefixos. |

Quatro métodos de teste, com 28 chamadas de avaliação na suíte final. Codex ausente
em outro ambiente gera skip apenas desses quatro métodos, sem tornar Codex
requisito da CLI. A validação nativa obrigatória desta tarefa foi executada aqui.

A documentação oficial consultada em docs/REFERENCES.md distingue execução fora
do sandbox, confiança/reinício, precedência e interpretação de wrappers no runtime.
Não foi iniciada uma sessão nova para observar prompts interativos; avaliação de
tokens não certifica a configuração efetiva de toda sessão/versão/superfície.
A regra instrucional para aprovar operações não cobertas consta de
CONTRATOS.md#git-e-permissoes. AGENTS encaminha a ela uma única vez no bloco SDD,
sem matriz duplicada na seção particular ou no template. Claude não é tratado
