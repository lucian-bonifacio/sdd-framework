# CLI pequena e recursos versionados por consumidor

Decisão histórica, substituída operacionalmente pela [ADR-003](ADR-003.md).
Não executar os controles antigos descritos neste registro.

## Contexto
O mantenedor autorizou construir a solução completa a partir das decisões da
conversa. Precisamos distribuir CLI, templates e uma skill para múltiplos agentes,
sem impor runtime de IA ao projeto. Instalação central é desejável; atualização
automática de instruções aprovadas de todos os projetos não é aceitável.

## Decisão
Usar Python 3.11+ com biblioteca padrão, CLI centralmente instalável e snapshots
versionados de recursos por consumidor. Uma skill SDD, com referências de fluxo
e contratos. Configuração JSON e Markdown com frontmatter YAML restrito.
Oferecer zipapp para instalação sem pip. CLI lê/verifica documentos; agente
interpreta e implementa. Essas escolhas são técnicas da implementação autorizada.

## Alternativas
CLI Node/TypeScript adicionaria toolchain de build para uma ferramenta textual.
Somente prompts não garantiriam inicialização reproduzível nem checagens estruturais.
Symlinks globais evitariam cópias, mas dificultariam Windows, snapshots e pinagem.
YAML completo exigiria dependência; o subconjunto explícito é suficiente para
metadados simples e listas de referências. MCP e servidor são desnecessários aqui.

## Consequências
Consumidores versionam pequenos recursos locais e atualizam explicitamente.
Política nova pode exigir upgrade da CLI. O verificador não prova qualidade
semântica; documentos e tarefas precisam de revisão real. Não há requisito de
instalação global para ler documentos ou continuar a implementação.
